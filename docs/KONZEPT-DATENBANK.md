# Konzept: Datenbank – Namen, Bereinigung und Erweiterungen (DEC-030)

Stand: **beschlossen** 12.11.2026 (#266), aus der Prüfung des Schemas im Chat vom 12.11.2026. Meilenstein «0.12.0 – API-
und DB-Cleanup». Umsetzung erst, wenn ein vollständiger Dump vorliegt (M0). Ergänzt
[KONZEPT-DATENMODELL.md](KONZEPT-DATENMODELL.md). Die Regeln für die Entwicklung fasst
[KONZEPT-DB-GUIDELINE.md](KONZEPT-DB-GUIDELINE.md) zusammen.

## Ausgangslage

- 23 Migrationen, 33 Tabellen (davon 7 von Laravel: Sessions, Cache, Jobs, Passwort-Rücksetzung).
- Die Tabellen sind weitgehend normalisiert. Gefunden: eine echte Doppelspeicherung (Suchbegriffe), fehlende
  Indizes und Fremdschlüssel, ungenutzte Felder und uneinheitliche Namen.
- **Noch nie produktiv ausgeliefert** (Chat 12.11.2026): Altlasten und Abwärtskompatibilität müssen nicht berücksichtigt
  werden. Daten auf dev bleiben aber erhalten – jede Änderung überführt bestehende Daten, nichts geht verloren.
- Die **API bleibt v1**. Ihre Feldnamen bleiben; die **Werte** von Status und Arten werden wie in der Datenbank englisch
  (O1, [KONZEPT-KONVENTIONEN.md](KONZEPT-KONVENTIONEN.md)).

## Namenskonzept

Weitgehend wird es heute schon so gehandhabt; neu ist, dass es festgeschrieben ist und die Abweichungen bereinigt
werden.

| Nr. | Regel                                                                                                                                                                                                                      |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| N1  | **Sprache:** Tabellen und Spalten englisch, `snake_case`. Anzeige deutsch über Labels im Code.                                                                                                                             |
| N2  | **Tabellen** im Plural (`terms`, `proposals`). **Verknüpfungen** `<besitzer_singular>_<ziel_plural>` (`term_categories`, `user_roles`). **Protokolle** `<objekt>_audit` (unveränderlich) bzw. `<objekt>_events` (Verlauf). |
| N3  | **Primärschlüssel** immer `id`: UUID für Fachobjekte und Konten (sichtbar in API, Sync, Links), fortlaufende Zahl für Protokolle, Ereignisse, Nummern und reine Hilfstabellen.                                             |
| N4  | **Fremdschlüssel** `<ziel>_id` bzw. `<rolle>_id` (`responsible_user_id`). Verweise auf die handelnde Person `<verb>_by_id` (`approved_by_id`).                                                                             |
| N5  | **Fremdschlüssel-Regel (E2):** Constraint immer, **ausser** der Verweis muss das Löschen einer Person oder Organisation überleben (Journal, Audit, Ereignisse, Einstellungen) – dann ohne Constraint, aber mit Index.      |
| N6  | **Zeit:** Zeitpunkt `<x>_at` (timestamp), Datum `<x>_on` (date), Zeitraum `valid_from`/`valid_until` (date).                                                                                                               |
| N7  | **Ja/Nein:** `is_<x>` oder `has_<x>`, nie verneint.                                                                                                                                                                        |
| N8  | **Status und Arten:** Spalte `status` bzw. `<x>_type`, Werte englisch `snake_case` als PHP-Enum (E4, O1); mit PostgreSQL zusätzlich CHECK-Regel. Liste der Werte in [KONZEPT-KONVENTIONEN.md](KONZEPT-KONVENTIONEN.md).    |
| N9  | **Mehrsprachige Texte:** Deutsch in der Haupttabelle, Französisch/Italienisch/Englisch in `<objekt>_translations` mit `locale` (X1).                                                                                       |
| N10 | **Abweichungen pro Organisation/Person:** `<feld>_override` in `organization_term_overrides` bzw. `term_user_overrides`.                                                                                                   |
| N11 | **Indizes** mit den Standardnamen von Laravel (`<tabelle>_<spalten>_index`, `_unique`, `_foreign`); **jede** Fremdschlüssel-Spalte ist indexiert.                                                                          |
| N12 | **JSON** nur für Abbilder, Protokolle und Listen ohne eigene Abfragen (`snapshot`, `changes`, `details`, `scopes`).                                                                                                        |

## Vorschläge für Erweiterungen

| Nr. | Vorschlag                                                                                                                                                                                                                                                                                                                                        | Nutzen                                                                      |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------- |
| X1  | **Übersetzungen:** `term_translations` (`term_id`, `locale` fr/it/en, `abbreviation`, `name`, `short_description`, `description`; eindeutig je Begriff und Sprache) und `category_translations`/`source_translations` (`name`, `label`, `description`). Aliase je Sprache über `term_aliases.language`.                                          | Glossar für die ganze Schweiz; API kann später `?lang=fr` anbieten.         |
| X2  | **Beziehungen zwischen Begriffen:** `term_relations` (`term_id`, `related_term_id`, `relation_type`: `successor` = Nachfolger, `see_also`, `broader`, `narrower`; eindeutig je Paar und Art).                                                                                                                                                    | Historische Begriffe zeigen auf den neuen; «siehe auch» in Detailansicht.   |
| X3  | **Mandanten für Intranet-Installationen:** Jede Intranet-Installation ist eine **Organisation** (UUID) mit eigenem Servicekonto. Sie synchronisiert nur `organization_term_overrides` und eigene Vorschläge, nie die gemeinsamen Werte. Neu `organizations.entra_tenant_id` (optional, eindeutig) für die Zuordnung bei der Microsoft-Anmeldung. | Mehrere Intranets parallel, ohne sich oder die gemeinsamen Daten zu stören. |
| X4  | **Suchen ohne Treffer:** `search_misses` (normalisierter Suchtext, Anzahl, erstes und letztes Auftreten; keine Person, keine IP-Adresse; Löschfrist 90 Tage).                                                                                                                                                                                    | Hinweise auf fehlende Abkürzungen für die Redaktion.                        |

## Migration ohne Datenverlust

| Nr. | Vorgehen                                                                                                                                                                                                                                                                                                                                        |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| M0  | **Vorbedingung:** Es liegt ein vollständiger Dump der dev-Datenbank vor (Chat 12.11.2026). Dafür gibt es zuerst den Dump als Funktion (#268): Befehl und Download in der Administration, mit oder ohne Passwort (später nur noch mit). Erst danach werden die Änderungen zusammengeführt (jedes Zusammenführen rollt auf dev aus und migriert). |
| M1  | Vor dem Ausrollen eine Sicherung der Datenbank (bestehender Sicherungsbefehl); Probelauf auf einer Kopie der dev-Datenbank.                                                                                                                                                                                                                     |

Offene Altwerte → Abbruch, bis sie in der Administration erledigt sind.                                                                                                           |
| M4  | Umbenennungen mit `renameColumn` (Daten bleiben); keine neu angelegten Tabellen mit Kopie, ausser SQLite verlangt es.                                                                                                                                                                                                                           |
