# EduKSX-Glossary – Entscheidungsregister V1.2
Stand: 07.11.2026

| ID | Status | Entscheidung |
|---|---|---|
| DEC-001 | Beschlossen | Eigenständige öffentliche Glossar-Webanwendung für Volksschulen, Schulgemeinden und Gemeinden. |
| DEC-002 | Beschlossen | Grunddatenstruktur des Glossary-Moduls aus `sek-intranet` als Referenz übernehmen. |
| DEC-003 | Beschlossen | Redaktionelle Pflege durch Recherche, Excel-Import/-Export und Community-Anträge mit Adminfreigabe. |
| DEC-004 | Beschlossen | EduKSX-Glossary ist führendes Datensystem; Konsumenten erhalten ausschliesslich veröffentlichte Daten. |
| DEC-005 | Beschlossen | Standardisierte REST-API ist Pflichtumfang; das Intranet muss regelmässig synchronisieren können. |
| DEC-006 | Beschlossen | Confluence ist ausschliesslich Datenempfänger; Glossardaten sollen als Seite in beliebigen berechtigten Spaces publizierbar sein. |
| DEC-007 | Beschlossen | Confluence-Publisher hat gegenüber Kern-API/Intranet niedrigere Priorität. |
| DEC-008 | Beschlossen | MCP-Server für künftige Rovo-Nutzung bereits architektonisch berücksichtigen; Implementierung nachrangig. |
| DEC-009 | Offen | Stack endgültig festlegen; Laravel/React wie Intranet ist Favorit. |
| DEC-010 | Vorschlag | PostgreSQL, OpenAPI 3.1, Sync-Release und Cursor-basierter Change-Feed. |
| DEC-011 | Vorschlag | MCP nutzt interne Application Services, nicht die Datenbank direkt; Rovo-Änderungen standardmässig moderieren. |
| DEC-012 | Offen | Hosting, Authentisierung, Confluence-Mehrfachziele und Rovo-Kompatibilitätsprüfung. |

Bei Widersprüchen zu V1.0/V1.1 haben DEC-004 bis DEC-008 Vorrang.
